# 11 — التصميم المقترح

## أ) التقويم (بلا تغيير في قاعدة البيانات)
زر تقويم في حقلي التاريخ يفتح `DatePickerDialog` (Material 3)؛ النتيجة تُملأ بصيغة `dd-MM-yyyy` وتُحوَّل لـ ISO قبل الإرسال (المحوّل موجود الآن). تاريخ النهاية لا يسبق البداية (يُمنع في المنتقي).

## ب) إنشاء المسابقات للكادر (يحتاج ترحيل DB بموافقتك)
- `contest_can_create()`: مدير النظام، المشرف، المحفظ، المانح.
- `contest_submit`: يحدد الحلقة المسموحة بحسب الدور (المحفظ: حلقاته من `halaqa_teachers`؛ المشرف: `halaqa_supervisors` و`halaqas.supervisor_id`؛ المانح: `donor_halaqas`؛ المدير: أي حلقة فعّالة).
- الحالة: مدير النظام → `approved` فورًا؛ غيره → `pending` للاعتماد (القرار الافتراضي، انظر القرارات).
- عمود `creator_role` لإظهار «من أنشأها». سياسات RLS تُعدَّل بالتوازي، والرؤية للجميع المتعلقين بالحلقة كما هي.
- الواجهة: زر «مسابقة جديدة» في شاشة المسابقات للأدوار الأربعة.

## ج) كفالة أولياء الأمور (يحتاج ترحيل DB بموافقتك)
- تعديل `rc32_is_observer()`-المحمية في `rc48_support_cards/pledge/my_pledges` إلى «مانح أو ولي أمر»؛ و`rc48_donor_scope_ok` لولي الأمر = حلقات أبنائه فقط (من `student_guardians` + `students.halaqa_id`).
- شاشة جديدة لولي الأمر «تكفّل بحلقة»: بطاقات الكفالة المفتوحة لحلقات أبنائه، تعهّد، «كفالاتي»، ثم متابعة التأكيد والإثبات كالمانح.
- ملاحظة خصوصية: بيانات الدفع في البطاقة (حساب/اسم) تظهر لولي الأمر كما تظهر للمانح؛ يؤكد المدير ذلك.

## د) الصفحة الخاصة والتذكيرات المحلية (بلا قاعدة بيانات)
- صفحة «المساهمة والمسابقات» لولي الأمر والمحفظ والمشرف: ما يمكنه فعله (كفالة/مسابقة)، وحالة طلباته، وإعدادات التذكير.
- `ReminderPrefs` في SharedPreferences: مفعّل/معطّل، اليوم/الأيام، الساعة، لكل نوع (كفالة، مسابقة). الإطفاء من الصفحة ومن الإعدادات.
- `ReminderScheduler` + `ReminderWorker` (WorkManager، عمل واحد متسلسل): يحسب التأخير حتى الوقت القادم، يعرض الإشعار عبر `NotificationHelper.show` بقناة جديدة `halaqati_reminders` (قابلة للإطفاء من إعدادات النظام أيضًا)، ثم يعيد الجدولة. النص ثابت داخل التطبيق ولا يقرأ من الخادم.
- إذن `POST_NOTIFICATIONS` يُطلب بسياق عند أول تفعيل (أندرويد 13+)؛ إن رُفض تظهر رسالة وتبقى الجدولة معطّلة.
- إعادة الجدولة عند فتح التطبيق وعند تغيير الإعداد، لتصحيح أي انحراف.

## الاختبارات
وحدات: حساب وقت التذكير التالي (مناطق زمنية/عطل/نهاية الأسبوع)، حالات التفعيل والإطفاء؛ Robolectric لصفحة الإعدادات والمنتقي؛ عقد قاعدة البيانات بالسكربت الموجود لدوال المسابقات والكفالة؛ تجربة التفافية للترحيل داخل معاملة تُلغى (كما فعلت مع RC112).

## خطة التنفيذ (مراحل مستقلة)
1. التقويم (بلا DB): أصغر مرحلة وأسرعها.
2. التذكيرات المحلية + صفحة الإعدادات (بلا DB).
3. مسابقات الكادر (ترحيل DB بعد موافقتك).
4. كفالة ولي الأمر (ترحيل DB بعد موافقتك).
5. صفحة ولي الأمر/الكادر الخاصة تجمع ما سبق.
كل مرحلة تُدمج وتُبنى بعد موافقتك، والنشر بموافقة منفصلة.
