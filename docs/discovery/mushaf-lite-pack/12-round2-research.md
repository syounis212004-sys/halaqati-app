# 12 Round 2: research summary (2026-11-25)

Triggered by the owner's new brief: do not adopt the single Hafs font as final; goals in order under 10 MB (ideal), under 25 MB (excellent), under 50 MB (acceptable); keep Quran text, harakat, waqf signs and the word/line/page layout; do not modify fonts whose licence forbids it; research variable fonts, composites, CFF/CFF2/WOFF2, specialised compression, vector/binary encodings, a light native engine, official KFGQPC sources, DigitalKhatt and similar projects, hybrids.

Roles (independent sub-agents, background, fresh context): R2A font technology and compression; R2B Android engineer; R2C open-source mushaf projects; R2D licence/terms (first run could not reach hosts, second run partial); R2E independent critic of the whole study. A separate reviewer audited PR #103. Reports are model output; the decisive claims below were re-verified by the author where marked **[verified]**.

## What the research found
1. **Lossless floor [measured by R2A, all 604 fonts: 207,809,084 B, 73.9M points, 108,995 glyphs, zero composites].** Raw 21.9 bits/point; WOFF2 13.0; solid transformed streams about 100 MB; zstd dictionaries about 108 MB; contour dedup about -12.5% of points; paq8px 11.3 bits/point (about 104 MB); CFF/CFF2 larger (p300 CFF2 317,942 B vs WOFF2 202,315 B), subroutinisation finds no repeats; variable-font families falsified (only 0.3% of points in non-identical interpolation-compatible groups). Best justified lossless combination about 85-95 MB (estimate, not built). **No lossless route reaches 50 MB.** It matches the author's earlier 107-111 MB and corrects the old "32 shared glyphs" figure: by outline 20.5% of glyph instances repeat across pages (7.2% of points).
2. **Official QF CDN families [R2E HEAD sizes, author re-measured V4].** v1/woff2 48.07 MB, v4/colrv1/woff2 50.88 MB (author: 50,878,540 B for pages, 604 files), v2/woff2 97.94 MB. Documented URLs: https://api-docs.quran.foundation/docs/tutorials/fonts/font-rendering/
3. **V1 is a different edition [verified].** API fields `line_v1`/`line_v2`/`v1_page`/`v2_page`: only 39 of 604 pages have identical per-line word counts in V1 and V2; 7,614 of 83,665 words sit on another line; 361 on another page. V1 fails the "same words on the same lines" rule against the current V2.
4. **V4 is a drop-in at the data level [verified].** All code_v2 of every page exist in the V4 font of the same page (604/604, 0 missing). V4 woff2 decodes to a file identical to the official V4 TTF (0 of 3,060 sampled glyphs differ, hinted and unhinted, 20 pages). Glyph advances differ from V2 (ratio 0.81-1.33 per glyph; line widths +3%, still constant per line), so V4 is a re-drawn print (1441H) with 6 CPAL palettes (COLR v0), not V2's outlines. The decoded TTF set is 167.3 MB, so only WOFF2 meets 50 MB and Android needs a decoder.
5. **DigitalKhatt [verified in part].** Precomputed layout `madina.json` (MIT repo; Madina font OFL 1.1): 604 pages (8-line pages 1 and 2), 850,327 positioned glyphs; the lab asset pack is **2,998,155 B** for all pages and outlines (gzip per page + glyph file 227 KB). No runtime shaping or justification is needed. See `14-dk-verification.md`.
6. **Android engine [R2B].** Precomputed positions + one Canvas per page + GraphicsLayer/Picture caching; no NDK, no WOFF2 needed if outlines ship as paths. woff2+brotli native lib 503 KB (arm64, stripped); HarfBuzz 971 KB-1.68 MB (arm64); CFF2/variable fonts need API 26. Current app minSdk 23. Per-word `Text` composables (today's engine) are the heaviest option. All timing figures are desktop proxies.
7. **Other projects [R2C].** Nothing found that is both glyph-identical to the KFGQPC print and under 50 MB. quran-madina-html (about 3.8 MB, 1441H lines from KFGQPC data, Waqf GPL 2.0), mushaf-android (DigitalKhatt demo, MIT, builds HarfBuzz+Skia natively), no "Quran Engine" project exists. DigitalKhatt's site is not an offline PWA (`ngsw.json` 404) and its whole web bundle is about 70 MB (madina.json 47 MB).
8. **Terms and licences [R2D, partial].** KFGQPC official pages unreachable from the agent; the page linked as "License" by qpc-fonts READMEs is dm.qurancomplex.gov.sa/copyright-2/ (not read). `ScanCode` lists the Uthmanic script licence as "Proprietary Free". DigitalKhatt issue #26 asks whether redistribution of the text needs KFGQPC permission (no reply seen). Tanzil text: CC BY 3.0 with a verbatim-only notice (from third-party copies, not Tanzil's page). Alternative datasets (quran-json) carry no page/line layout. zonetecde/mushaf-layout takes layout from Quran.com fields (so QF terms may flow).
9. **Errors found in round 1 [R2E]:** the V1/V4 families were missed (REPORT claim "no tested option" overclaimed); Option 2 "NO" should read "ambiguous, needs written confirmation" (Play Asset Delivery is a clean bundling path); the score for Option 7 counted size and look from different outcomes; E2 own-codes ignored 361 words that use another page's font. These are amended in `13-options-round2.md`.

## 10 Found late: the app already bundles the 1441H (QCF4) page/line layout [FACT, code]
`source/app/src/main/assets/quran/qcf4-layout-v2.bin` (18,708 B) and `qcf4-layout-source.json`: a verse-level page/line layout (6,236 ayahs, 604 pages, 15-line model) taken from `MohamadHajjRabee/quran-qcf4` `verses.json` at commit `5130511027e769f0a8f4eeb7f00f46bde3788d60`. `QuranCore.kt` loads it for the range/line engine (`QuranRangeEngine`, used by plans and scoring). It holds no Quran text. Consequences: (1) the app's own line arithmetic follows the **1441H** layout while the mushaf viewer draws **V2** (1421H) pages, which differ on a handful of pages (DigitalKhatm's 1441H data differs from V2 on 7 pages); a V4 or DigitalKhatm viewer would make both agree; (2) some page/line data is already independent of Content Sync; its licence ("respect the original creator's terms" per R2C) should be checked as part of the compliance plan; (3) the upstream project is the same source DigitalKhatm's `quran-madina-html` cites for its 1441H line breaks.
