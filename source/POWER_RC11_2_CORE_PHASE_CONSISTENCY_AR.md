# Halaqati v2.46.2 — RC11.2 Core Phase Consistency

هذا الإصدار يثبت RC11 كمحرك مراحل فعلي بدل طبقة واجهة فقط.

## ما تم تنفيذه
1. **Lifecycle للمراحل**: Scheduled / Active / Ended / Completed مع reconciliation للمرحلة المنتهية حتى لو لم يضغط المشرف «إنهاء». النتيجة المجمدة لا تعود صفرًا عند تعديل التاريخ.
2. **مصدر حقيقة واحد**: بعد وجود مراحل، `smart_plans` يصبح حاوية توافق؛ هدف/تواريخ/أيام/نطاق الحفظ والسرد تعدّل من المراحل، وتبقى الخطة الأم متزامنة مع حدود المراحل.
3. **Backfill آمن**: Migration تربط التسميعات القديمة بـ`phase_id` فقط عندما يوجد تطابق واحد غير ملتبس، وتستبعد `test` من Sard Anchor.
4. **Timeline validation**: مرحلة حفظ واحدة + مرحلة سرد واحدة، منع overlap، إظهار gap بوضوح، وعدم تغيير نوع مرحلة لها تاريخ طلاب.
5. **Sard Anchor موحد**: `SardAnchorResolver` يعتمد `session_date` ثم `created_at`، ولا يتحرك بواسطة اختبار عام.
6. **اتجاه السرد**: للحفظ العام الافتراضي `الناس → البقرة` بين السور مع بقاء الآيات تصاعدية داخل السورة، ويمكن للمشرف تغييره إلى `البقرة → الناس`.
7. **الانتقال الجماعي**: RPC ذرية/idempotent تنهي الحفظ وتبدأ السرد وتكتب الأحداث داخل عملية واحدة، مع هدف سرد Override لكل طالب عند الحاجة.
8. **Optimistic concurrency**: تعديل المرحلة يستخدم `revision` ويظهر Conflict بدل أن يمسح تعديل جهاز آخر.
9. **أسبوع الطالب**: يعتمد على الجلسة الفعلية والحضور والتسميع والمرحلة التاريخية؛ عدم وجود تسميع لا يعني إجازة، والسبت فقط هو الإجازة الثابتة حسب سياسة الحلقة الحالية.
10. **تقارير Phase-aware**: الحفظ والسرد يستخدمان `phase_id` والنتائج المجمدة أولًا، مع fallback محدود للبيانات القديمة غير المصنفة.
11. **القوالب**: دورة الخطة هي المرجع، بما في ذلك الخطط التي تعبر نهاية الشهر؛ السرد الافتراضي 25 صفحة.
12. **الإشعارات**: بدء السرد لا يرسل قبل تاريخ البداية، وsource keys ثابتة لمنع التكرار.
