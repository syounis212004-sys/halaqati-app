# حلقاتي v2.60.0 RC24 — محرك الشهادات والأرشيف الرسمي

يركز RC24 على إصلاح الشهادات من الجذر بعد ظهور شهادات يكون رأسها وتذييلها صحيحين بينما يختفي جسم الشهادة. أصبح محرك الشهادة واحدًا للمعاينة وPDF، ويمنع الإصدار إذا كان عنوان الشهادة أو اسم الطالب أو نص الإنجاز فارغًا أو خارج حدود A4 أو متداخلًا مع منطقة التاريخ/التوقيعات/التذييل.

## التصميم والرسم

- عبارة **«شهادة تقدير وإنجاز»** أصبحت مباشرة تحت الزخرفة/المعيّن العلوي دون ربط موضعها بحجم الشعارات أو negative margins.
- المعاينة A4 وملف PDF يستخدمان HTML/CSS نفسه؛ لا يوجد قالب ثانٍ للـPDF.
- Render Gate منظّم يفحص: وجود العناصر، ظهورها، أبعادها، بقاؤها داخل A4، وعدم تداخلها مع المناطق المحمية.
- النصوص الطويلة تخضع لـ auto-fit بحدود قراءة دنيا بدل إسقاط النص أو إخفائه.
- ملفات PDF والشعارات والتواقيع والختم **تبقى محليًا على الجهاز ولا تُرفع إلى Supabase**.

## الأرقام الرسمية

الأرقام الجديدة تستخدم الصيغة:

`HAL-CERT-YYYY-CODE-NNNNN`

والسلاسل الافتراضية هي:

- `G` عام / تقدير.
- `S` السرد.
- `K` ختم القرآن.
- `M` التميز الشهري.
- `I` الطالب المثالي.
- `R` المراكز / التفوق.
- `C` مخصص.

لكل سنة وسلسلة عداد مستقل. تعديل رمز السلسلة يؤثر في **الأرقام المستقبلية فقط** ولا يعيد كتابة أي رقم رسمي صدر سابقًا.

## الأرشيف والإصدارات

يدعم الأرشيف الرسمي تسلسل `v1/v2/v3` تحت الرقم الرسمي نفسه.


- الشهادة الرسمية تبقى بهوية ورقم واحد.
- التصحيح لا يحرق رقمًا جديدًا؛ ينشئ `v2` ثم `v3` ... تحت الرقم الرسمي نفسه.
- لا يمكن في التصحيح تغيير الطالب أو سنة الإصدار أو السلسلة؛ هذه التغييرات تتطلب شهادة جديدة.
- الشهادة الصادرة تُلغى رسميًا مع بقاء الرقم والسجل بدل حذفها بصمت.
- يمكن إضافة سجل شهادة تاريخية برقم يدوي دون استهلاك رقم من العدادات الجديدة.
- الأرشيف المحلي أصبح revision-aware ولا يدمج `v1` و`v2` لمجرد أنهما يحملان الرقم نفسه.
- إذا كانت شهادة قديمة لا تحتوي Snapshot كاملًا، تُعرض كـ `legacy_partial` ولا يخترع التطبيق نصًا أو أصلًا بصريًا غير موجود.

## ترحيل Supabase

Migration RC24:

`migration/20261009_v2600_rc24_certificate_archive_rendering_core.sql`

يضيف `certificate_series` و`certificate_revisions`، ويوسع `certificates` ببيانات السلسلة والإصدار الحالي، ويحوّل عدادات الأرقام إلى `(issue_year, series_key)`، ويضيف RPCs إصدار/تصحيح/إلغاء/استيراد تاريخي.

**قاعدة Supabase الإنتاجية الحالية تم تطبيق RC24 عليها بالفعل. لا تعِد تشغيل ملف SQL يدويًا على نفس Production.** الملف المرفق مع الإصدار للتوثيق والبيئات الجديدة فقط. CI لا ينفذ DDL على قاعدة الإنتاج.

## حماية الأرقام القديمة

الأرقام القديمة مثل:

`HAL-CERT-2026-00009`

تبقى كما هي حرفيًا. لا يقوم RC24 بإعادة ترقيمها. تُنشأ لها Revision تاريخية خفيفة من البيانات المتاحة، وإذا كان النص الأصلي ناقصًا تُوسم `legacy_partial=true`.

## فحوص ما بعد الترحيل

```sql
-- السلاسل الافتراضية السبعة
select series_key, code, active from public.certificate_series order by series_key;

-- الرقم القديم المرجعي لا يتغير
select certificate_number, legacy_number, legacy_partial, revision_count
from public.certificates
where certificate_number='HAL-CERT-2026-00009';

-- لا توجد أرقام إصدارات مكررة لنفس الشهادة
select certificate_id, revision_no, count(*)
from public.certificate_revisions
group by certificate_id, revision_no
having count(*) > 1;

-- المفتاح المركب للعداد
select pg_get_constraintdef(oid)
from pg_constraint
where conrelid='public.certificate_number_counters'::regclass and contype='p';
```
